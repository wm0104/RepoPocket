# RepoPocket 项目架构分析

分析日期：2026-10-17。本文通过 CodeGraph 查询当前源码及引用关系，并结合 README、项目配置与 CI 工作流整理，供后续 AI 和开发者快速理解项目。属于静态架构分析，不代表已通过编译、网络操作或真机验证。

## 1. 这个软件是做什么的

RepoPocket 是面向 iOS 16 及以上系统的 GitHub 工具。主要用途是在手机上浏览仓库、阅读代码与 README、下载文件、管理仓库内容和发行版，同时处理本地项目的 Git 操作。README 将 TrollStore 作为使用场景。

源码入口实际提供四个标签：仓库、Git、提交 / 发布、设置。它既包含 GitHub API 驱动的远端管理，也包含原生 Git 引擎驱动的本地项目操作，理解项目时应区分这两条路径。

## 2. 当前入口与模块关系

入口为 `RepoPocket/RepoPocketApp.swift` 中的 `RepoPocketApp`，由 `AccountRootView` 组织标签页。账号切换通知会更新根视图标识，从而重新构建账号相关界面。

## 3. 三条关键处理路径

### 仓库浏览

`AccountRootView → RepositoriesView → BrowserView → GitHub API 方法`

`BrowserView` 持有仓库、路径、分支和加载状态。仓库概览连接社区区块、发行版与工作流摘要、代码目录、提交历史和 README；目录行再进入子目录或 `FileView`。写入能力会参考远端权限及当前会话是否匹配，不能把“能浏览”理解成“能提交”。

### 当前本地 Git

`AccountRootView → LocalProjectsView → LocalProjectView`

底层服务由 `LocalGitEngine` 提供：请求经过目录授权、文件协调、目录身份校验，然后编码为 JSON 调用 `rp_git_execute`，再解析返回结果。它使用一条 utility 队列限制并行 CPU / IO 工作，并把取消请求传到 `rp_git_cancel`。

`LocalGitRegistry` 将项目记录保存在 Application Support 的 `LocalGit/projects.json`。有 `.git` 的项目使用原目录仓库；没有 `.git` 的项目通过 `usesPrivateGit` 标记选择私有 Git 数据目录。移除项目关联只将记录置为非活动，源码明确保留文件、元数据与未推送提交，便于重新关联。

界面明确说明：外部编辑后手动下拉刷新，提交和推送分别操作。

### GitHub API 快照工作区

`GitHub.preparePull → WorkspacePull → WorkspaceView → LocalStore.applyPull`

这条路径以 `WorkspaceBinding` 保存仓库、分支、远端 head、tree、文件模式和基线快照。拉取时比较基线、本地和远端，生成冲突信息。

`LocalStore.applyPull` 检查本地快照和基线是否变化，在暂存目录应用结果并验证，再通过备份与替换更新工作区；失败时尝试恢复。当前源码拒绝对关联原目录执行这种拉取覆盖。因此，不应把此路径的限制直接套用到原生本地 Git 模块。

远端提交 `GitHub.commitWorkspace` 使用 GitHub Git 数据接口创建 blob、tree、commit，更新分支前两次核对 head，并以 `force: false` 更新引用。这与本地 Git 提交、推送是不同实现。

## 4. 容易误判的地方

1. **旧 Git 页面不是当前入口。** `GitWorkspaceView.swift` 明确注明已退役，仅保留用于兼容测试夹具；`GitCore.swift` 内仍有“下一阶段接入 libgit2”的旧注释。当前标签实际使用 `LocalProjectsView`，不能据旧代码得出“本地 Git 尚未实现”的结论。
2. **快照工作区和原生 Git 并存。** 分析刷新、提交、拉取或冲突时，应先查清具体页面和调用路径。
3. **CodeGraph 的结果需要判断相关性。** 本次宽泛查询曾带回无关符号；指定完整文件路径后返回更准确。工具提示某个符号附近“未找到测试”，只说明图查询未建立相应联系，不代表仓库没有测试。
4. **索引数量不是完整覆盖证明。** 初始化记录为 144 个文件、3,590 个节点、7,007 条关系；此数字是当时快照，不能证明所有语言、桥接和运行时行为均被正确解析。

## 5. 界面与状态约定

`WorkspaceSelectionUI.swift` 提供 `SoftGroupRows`、`SoftGroupRow`、`softGroupedRow` 和 `SoftGroupShape`。源码使用 22 点连续圆角，并由实际首尾行计算分组边界。新增或调整分组界面时应复用这套组件，检查条件行、展开收起后的边界和分隔线。

账号元信息与活动账号标识存放在 UserDefaults；凭据通过 `CredentialStore` 的 Security 接口管理。`AccountStore.generation` 参与阻止旧账号任务继续工作。后续修改异步功能时，应跟踪会话切换、取消处理和结果写回时机。
